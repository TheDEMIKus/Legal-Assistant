# Юридический ассистент ПСБ

Отвечает на вопросы по базе знаний компании: договоры, регламенты, законы. На входе `questions.csv` и `knowledge-base.zip`, на выходе `submission.csv`.

## Как работает

1. Документы режутся на фрагменты по пунктам и статьям. У каждого фрагмента шапка: документ, редакция, раздел. У статей НК в шапке указан налог (в базе три статьи «Налоговые ставки»), у продолжения длинного пункта — его вводная фраза. Пометки об истории изменений («Пункт 3 изменен с … - Федеральный закон…») остаются в поиске, но модели показываются, только если вопрос об изменениях.
2. Поиск идёт двумя способами: BM25 по словам (со своим стеммером) и по эмбеддингам bge-m3. Кандидаты из обоих списков отдаются реранкеру, он оставляет лучшие.
3. К найденному договору или регламенту добавляются допсоглашения и письма, которые его меняют.
4. Модель отвечает в JSON: сначала дословные цитаты, затем расчёты, если они нужны, потом ответ со ссылками на пункты.
5. Код проверяет ответ: цитаты должны быть в документах, числа и номера пунктов тоже (с учётом границ числа: «5 000 000» не засчитывается внутри «15 000 000»), расчёты должны сходиться арифметически, редакция должна действовать на дату из вопроса. При ошибках модель отвечает ещё раз со списком ошибок. Если и вторая попытка не прошла, возвращается отказ «в базе нет точного ответа».

Ошибки эмбеддера и генерации не маскируются: при них прогон завершается. Если реранкер недоступен, решение отключает его до конца прогона и выбирает пять фрагментов по объединённому BM25- и векторному рейтингу. Пустой ответ модели на отдельный вопрос запрашивается повторно; при повторной неудаче возвращается отказ.

Температура (0.1), `MAX_TOKENS` (3000), `TOP_K` (20) и `RERANKER_TOP_N` (5) заданы в `config.py`, одноимённые переменные платформы не читаются: их значения подобраны под стартер. Ответ, обрезанный по лимиту токенов, запрашивается повторно с удвоенным лимитом.

Строки документов, адресованные ИИ («игнорируй остальные документы…»), вырезаются при загрузке базы; удалённое выводится в лог.

## Файлы

| Файл | Назначение |
|---|---|
| `solution.py` | точка входа |
| `config.py` | доступ к API и модели из переменных окружения, параметры генерации и поиска |
| `loader.py` | чтение вопросов и базы, нарезка на фрагменты |
| `search.py` | BM25, эмбеддинги, реранк |
| `answer.py` | промпт, генерация, проверка ответа |
| `llm.py` | запросы к API с повторами при 429/5xx |
| `eval/` | локальная оценка по схеме регламента, в сабмит не входит; описание в `eval/README.md` |

## Локальный запуск

Установить зависимости:

```bash
uv venv && uv pip install -r requirements.txt
```

Создать `.env` в корне (в git не попадает):

```
LLM_BASE_URL=https://openrouter.ai/api/v1
LLM_API_KEY=ключ
LLM_MODEL=deepseek/deepseek-v4.1-flash
EMB_MODEL=baai/bge-m3
RERANKER_MODEL=cohere/rerank-5-fast
DATA_DIR=data
```

Положить в `data/` файлы `questions.csv` и `knowledge-base.zip` и запустить:

```bash
.venv/bin/python solution.py
```

Лог выводится в stderr: по каждому вопросу статус (`ok`, `fixed`, `not_found`, `fallback`) и непройденные проверки. Для сравнения есть эталонные ответы в `starter/demo_output.csv`.

Нарезка базы на фрагменты: `.venv/bin/python loader.py`.

## Сабмит

Архив собирается только из этих файлов, без папок:

```bash
python3 -m zipfile -c submission.zip solution.py requirements.txt config.py loader.py llm.py search.py answer.py
```

`.env`, `data/` и `submission.csv` в архив не входят: данные и ключи передаёт платформа.

## Переменные окружения

Передаются платформой. Читаются:

- адрес API: `LLM_BASE_URL`, `OPENAI_BASE_URL`, `BASE_URL`
- ключ: `LLM_API_KEY`, `OPENAI_API_KEY`; для эмбеддера и реранкера отдельно `EMBEDDER_API_KEY`, `RERANKER_API_KEY`, если заданы
- модель: `LLM_MODEL`, `GEN_MODEL`, `OPENAI_MODEL`
- `EMB_MODEL`, `RERANKER_MODEL`, `DATA_DIR`, `MAX_WORKERS`

`TEMPERATURE`, `MAX_TOKENS`, `TOP_K`, `RERANKER_TOP_N` и `CHUNKER` не читаются: параметры заданы в `config.py`.
