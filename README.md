# Юридический ассистент ПСБ

Отвечает на вопросы по базе знаний компании: договоры, регламенты, законы. На входе `questions.csv` и `knowledge-base.zip`, на выходе `submission.csv`.

## Как работает

0. Классификатор (эмбеддинги + логистическая регрессия) делит вопросы на «по делу», «не по теме» и «атака». Не по теме и атаки получают вежливый отказ без поиска и генерации. Обучается при каждом запуске на примерах из `guard_data.py`, порог подбирается автоматически так, чтобы на обучающем наборе не блокировался ни один нормальный вопрос.
1. Документы режутся на фрагменты по пунктам и статьям. У каждого фрагмента шапка: документ, редакция, раздел.
2. Поиск идёт двумя способами: BM25 по словам (со своим стеммером) и по эмбеддингам bge-m3. Кандидаты из обоих списков отдаются реранкеру, он оставляет лучшие.
3. К найденному договору или регламенту добавляются допсоглашения и письма, которые его меняют.
4. Модель отвечает в JSON: сначала дословные цитаты, потом ответ со ссылками на пункты.
5. Код проверяет ответ: цитаты должны быть в документах, числа и номера пунктов тоже, редакция должна действовать на дату из вопроса. При ошибках модель отвечает ещё раз со списком ошибок. Если и вторая попытка не прошла, возвращается отказ «в базе нет точного ответа».

Технические ошибки (нет ключа, упал API, не работает реранкер) не маскируются: скрипт падает с трейсбеком.

## Файлы

| Файл | Назначение |
|---|---|
| `solution.py` | точка входа |
| `config.py` | все настройки из переменных окружения |
| `loader.py` | чтение вопросов и базы, нарезка на фрагменты |
| `search.py` | BM25, эмбеддинги, реранк |
| `answer.py` | промпт, генерация, проверка ответа |
| `guard.py` | классификатор вопросов |
| `guard_data.py` | обучающие примеры для классификатора; модуль, а не CSV, потому что в ZIP допускаются только `.py` |
| `llm.py` | запросы к API с повторами при 429/5xx |

## Локальный запуск

Установить зависимости:

```bash
uv venv && uv pip install -r requirements.txt
```

Создать `.env` в корне (в git не попадает):

```
LLM_BASE_URL=https://openrouter.ai/api/v1
LLM_API_KEY=ключ
LLM_MODEL=deepseek/deepseek-v4.1-flash
EMB_MODEL=baai/bge-m3
RERANKER_MODEL=cohere/rerank-5-fast
DATA_DIR=data
```

Положить в `data/` файлы `questions.csv` и `knowledge-base.zip` и запустить:

```bash
.venv/bin/python solution.py
```

Лог выводится в stderr: по каждому вопросу статус (`ok`, `fixed`, `not_found`, `fallback`, `blocked`), решение классификатора и непройденные проверки. Для сравнения есть эталонные ответы в `starter/demo_output.csv`.

Нарезка базы на фрагменты: `.venv/bin/python loader.py`.

Оценка классификатора: `.venv/bin/python guard.py`. Выводит порог, точность на кросс-валидации и решение по каждому вопросу из `data/questions.csv`.

## Сабмит

Архив собирается только из этих файлов, без папок:

```bash
python3 -m zipfile -c submission.zip solution.py requirements.txt config.py loader.py llm.py search.py answer.py guard.py guard_data.py
```

`.env`, `data/` и `submission.csv` в архив не входят: данные и ключи передаёт платформа.

## Переменные окружения

Передаются платформой. Читаются все имена из регламента:

- адрес API: `LLM_BASE_URL`, `OPENAI_BASE_URL`, `BASE_URL`
- ключ: `LLM_API_KEY`, `OPENAI_API_KEY`; для эмбеддера и реранкера отдельно `EMBEDDER_API_KEY`, `RERANKER_API_KEY`, если заданы
- модель: `LLM_MODEL`, `GEN_MODEL`, `OPENAI_MODEL`
- `EMB_MODEL`, `RERANKER_MODEL`, `DATA_DIR`, `TEMPERATURE`, `MAX_TOKENS`, `MAX_WORKERS`, `TOP_K`, `RERANKER_TOP_N`
